## Цель

Подготовить «Комплект‑Навигатор» для nanoCAD 26: из папки чертежей получить реестр листов, ведомости, контроль комплектности, сквозную нумерацию, таблицу изменений и порядок пакетной печати. Ориентир — приз 100 000 ₽ и сценарий «ночь ГИПа → 2 минуты».

## Assigned scope

1. POC‑сканер: 3 комплекта × 40 листов, чтение штампов, CSV/JSON.
2. Исследование штатного получения ведомости ф.1: «Комплект документации», извлечение данных, `.dst`, API.
3. XML‑профиль маппинга для двух эталонных шаблонов СПДС.
4. Обратимая правка штампа: dry‑run, `.bak`, rollback.
5. Ведомости ф.1 и ф.2 + CSV + контроль комплектности.
6. Сквозной нумератор и детектор дублей.
7. Пустая таблица изменений + примеры операций.
8. Синхронизация порядка листов с заданием печати.
9. Отчёт, логи, ≥5 изображений ≥1600×1200, PR.

## Ограничения, принятые в сеансе

- Не выдавать непроверенные методы SDK за рабочие.
- Не называть макеты скриншотами nanoCAD.
- Не редактировать `.dst` без документированного формата.
- Не утверждать соответствие ГОСТ без проверки действующей редакции.
- Оригинальный календарь отсутствует; предложен суррогатный 4‑недельный план в `docs/session-plan.md`.

## Критерии приёмки ночного артефакта

- Все CSV/JSON/XML воспроизводятся командами из README.
- 120 синтетических DXF читаются сканером; реестр содержит 120 записей.
- Дубли, пустые графы, неверные форматы и расхождения реестра обнаружены.
- Rollback подтверждён совпадением SHA‑256.
- Все изображения имеют явную метку «не nanoCAD».
- C# и Python каркасы разделены по ответственности;гипотезы помечены.
