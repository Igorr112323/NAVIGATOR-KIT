## Архитектура и границы результата

`linux_stand/core/`: geometry, ICadBackend (Protocol), vedmist, normcontrol — без CAD API.
`dxf_backend.py`: реальная реализация на ezdxf.
`independent_reader.py`: отдельный читатель пар DXF без ezdxf и без парсера приложения.
`multicad_backend.py`: **явный NotImplementedError**, не фиктивный рабочий backend.
Существующее C#-ядро и прежний pipeline не заменены: это изолированный первый стенд.
Парсер нового стенда поддерживает только подготовленный NK_STAMP, не все 120 профилей.

Порт Python → C# ещё предстоит; обещание «поменять один файл» сейчас неприменимо.
После переноса ядра и подтверждения SDK следует отдельно проверить транзакции,
блоки/атрибуты, кодировки и шрифты, layouts, единицы, печать, rollback,
McCustomBase, ручки/реакторы при их использовании. Проверки геометрии не доказывают
совпадение визуализации или поведения в nanoCAD.

## Что сделать до следующего раза

1. Подключить два существующих XML-профиля штампов и реальные подготовленные DXF.
2. Добавить отрицательные fixtures, вложенные блоки и трансформации, затем сравнить с текущим реестром 120 листов.
3. Уточнить геометрию по официальному тексту ГОСТ; не выдавать демо за форму 1/2.
4. Перенести контракт ядра в C#, прогнать одинаковые fixtures на обоих языках.
5. На Windows/nanoCAD 26 проверить SDK и настоящий адаптер, снять реальные скриншоты.

## Завершение пакетного Linux-стенда

Дополнительный воспроизводимый запуск (после основной цепочки):
```sh
python tools/run_linux_stand.py
python tools/complete_linux_stand.py
python tools/finalize_delivery.py
python tools/finalize_linux_stand.py
```

- `samples/stamp_01.dxf` … `stamp_12.dxf`: 12 отдельных контролируемых штампов.
- `../screenshots/linux_stamp_01.png` … `linux_stamp_12.png`: рендеры сохранённых DXF,
  1600×1200, предупреждение сверху и постоянный watermark справа снизу.
- `parsed_stamps.json`, `parser_diff.log`: независимая перечитка всех 12 DXF,
  сравнение значений с ожидаемыми; исходный hello-DXF также сравнивается с verification.json.
- `pytest.log`, `pytest.xml`, `test_report.json`: полный pytest и отдельный результат
  delivery-verifier. **59 delivery checks не являются 59 pytest-тестами.**
- `log.txt`: stand_status: ready относится только к Linux DXF, не к CAD-интеграции.
- `../navigator-kit-linux-stand.zip`: отдельный пакет ≤3 MB; содержит исходники и тесты,
  fixtures, рендеры, данные, XML и журналы. Сам себя и другие ZIP не включает.

Исходники не дублируются в delivery: парсер — `linux_stand/core/vedmist.py`,
рендер — `linux_stand/render.py`, тесты — `tests/`, CLI независимой перечитки —
`tools/independent_dxf_parser.py`. Число тестов в JSON фактическое, может быть >25.

Ограничения: четыре поля пока DESIGNATION/SHEET/TITLE/FORMAT, марка отдельно не извлекается.
Рамка фиксированная 297×210; A1/A2/A3, поворот, масштаб INSERT, вложенные блоки и
несколько штампов не поддержаны. Это не универсальный независимый CAD-парсер.
В DXF **40** — высота TEXT/ATTRIB; **39** — толщина (не высота текста).
Размер PNG проверяется по факту; диапазон 20–30 KB не является доказательством качества.
Нормативные тексты не скачивались повторно: доступны сохранённые ссылки/выдержки,
геометрия форм и SDK по-прежнему ГИПОТЕЗА/ПРОВЕРИТЬ.
