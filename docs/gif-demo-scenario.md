# Сценарий реального GIF-демо nanoCAD 26

Подготовлен в Linux 2026-10-29. Реальное видео НЕ снято. Это план приёмки будущей
интеграции, а не перечень уже работающих кнопок. Лента «Комплект документации»,
«Показать реестр», «Сдвинуть номера», export print_settings.ini и SheetSetManager
не подтверждены для нашего плагина — НЕ изображать их как существующие функции.

## Gate перед съёмкой

Сначала выполнить docs/windows-stand-setup.md, подтвердить SDK/команды и реальный
адаптер чтения/записи/rollback/layouts. Сейчас есть portable pipeline, не такой UI.
Если адаптера нет, снять только открытие подготовленных DXF в nanoCAD и отдельно
показать CSV/CLI как внешний стенд с явной подписью. Не склеивать это в «работающий плагин».

## Сюжет 10–15 секунд (5 кадров/с, 3–5 копий тестовых DXF)

| Время | Действие | Доказательство / условие |
|---|---|---|
| 0–2с | Папка с копиями stamp_01…05.dxf → открытие DXF | Видны пути, нет production-данных/секретов |
| 2–5с | Реестр листов | Только реальная реализованная команда/UI; иначе отдельно CSV и подпись «внешний CLI» |
| 5–8с | Правка TITLE или SHEET | До/после, .bak, SHA-256; не менять FORMAT под видом марки |
| 8–11с | Сдвиг SHEET на +1 | До/после и rollback; не обещать нереализованную кнопку |
| 11–15с | Порядок печати | Показать print_order.json как handoff, либо реальный диалог после SDK-интеграции |

В текущих DXF четыре поля DESIGNATION/SHEET/TITLE/FORMAT, отдельного MARK нет.
A1/A2 — форматы, не марки. Layout-имена в данных не гарантируют реальные paper layouts:
проверить в nanoCAD перед съёмкой. Экспорт .ini и масштаб 1:100 не предписывать без
поддержки. Штатный SHEETSET сам по себе не подтверждает работу нашего плагина.

## Запись и упаковка (на Windows, после готовности)

Можно использовать разрешённую программу записи экрана/LICEcap; сохранить исходник.
Не снимать лицензионные ключи, почту и закрытые проекты. Добавить правдивый баннер
`nanoCAD 26 / реальный стенд`; снимки внешнего CLI отмечать отдельно.
Для **подготовленного видео input.mp4** пример ffmpeg:

```sh
ffmpeg -i input.mp4 -filter_complex "fps=5,scale=800:-1:flags=lanczos,split[a][b];[a]palettegen=max_colors=64[p];[b][p]paletteuse=dither=bayer" -loop 0 demo.gif
```

Здесь корректные фильтры palettegen/paletteuse; paletteoptimize не предполагается.
Команда в sandbox не выполнялась (ffmpeg отсутствует). Если >3 000 000 байт,
уменьшить длительность, fps, ширину/палитру и повторить; лимит не гарантирован командой.
Проверка размера в PowerShell: `(Get-Item demo.gif).Length -le 3000000`.

## Приёмка

- [ ] Видны 5 шагов, подписи читаемы, 10–15 секунд.
- [ ] Файл ≤3 000 000 байт, GIF открывается и воспроизводится.
- [ ] Сохранён исходник записи и журнал фактических команд.
- [ ] Нет имитации несуществующего UI/автоматизации или смены марки через A1/A2.
- [ ] Границы проверенного SDK/rollback/печати перечислены отдельно.
